# 第2段階（予約改善）の設計（2026-11-04）

もとの指示書の「4 予約・キャンセル対策」と「9 第2段階」。第1段階（集客の4タブ・計測・自動化設定）は #52 で入った。
予約の正本は予約システム（GAS。`Documents/予約管理表/Code.gs`。Apps Script エディタへ貼り付けて再デプロイする運用）。
院内アプリ（このリポジトリ）は「送るかどうかの最後の関門」と「記録・画面」を受け持つ。

## 調べて分かったこと（予約システム）

| こと | いま |
|---|---|
| 予約の状態 | `確定`・`来院済み`・`キャンセル` の3つ（無断キャンセルの区別なし） |
| 患者さんの LINE へ送る印 | 予約の行の `LINE通知キー`（署名つき。生の LINE の ID は持たない） |
| 予約確定・キャンセルの LINE | GAS → `/api/marketing/reservation-notify`（`patient-confirm`・`patient-cancel`）。#52 で自動化設定の関門つき |
| 前日のお知らせ | メールだけある（`sendTomorrowReminderEmails`・毎朝8時・`確定`の行だけ・`前日通知日時`が空の行だけ）。院長あての前日一覧は LINE |
| 同意 | 予約フォームに個人情報の同意チェックはある。お知らせを受け取るかの選択はない |

## 作るもの

### 1. 前日リマインド（LINE）
- GAS：毎朝の前日のお知らせで、`確定` かつ `LINE通知キー` がある行は LINE で送る（メールの方はメール）。1つの予約に1回だけ（`前日通知日時` を共通で使う）。送る直前に状態を読み直し、`キャンセル`・日時が変わった予約には送らない
- 院内アプリ：`reservation-notify` に `patient-remind` を足す。自動化設定に「前日リマインド」を足し、**既定はテスト**（院長の LINE にだけ見本）。1日の上限・動いた記録つき
- 文面：日時・場所・変更とキャンセルの方法だけ（来院を強くすすめる言葉・施術の指示は入れない）

### 2. 同意の記録（marketing_consents）
- 目的を2つに分けて持つ：**予約のお知らせ**（確定・前日・キャンセル）と **お知らせ・ご挨拶**（誕生日など）
- 予約フォーム（GAS の画面と LINE の予約）に「前日に LINE（メール）でお知らせを受け取る」のチェックを足し、予約の行に残す。未成年の方は保護者の連絡先・同意を前提にする
- LINE で「配信停止」と送る・メニューから押すと、お知らせ・ご挨拶を止める（予約のお知らせは別に止められる）。誕生日の送信は止めた方に送らない
- 院内アプリの保存先は KV の `mkt:consent:`（LINE の ID はハッシュにして持つ）

### 3. キャンセル待ち
- GAS：シート「キャンセル待ち」（希望日・時間帯・LINE通知キー・受付日時・状態）。LINE の予約で満席の日に「キャンセル待ちに登録」を出す
- キャンセルが出たら、その日・時間帯の希望者へ**先着順に1人ずつ**知らせる（同じ枠に同時に何人も送らない）。案内は「先着順で、この連絡は予約の確定ではない」と書き、予約ページへ誘導。一度知らせた方には同じ枠で二度送らない。過ぎた日の登録は自動で終わり
- 院内アプリ：`patient-waitlist` を足し、自動化設定に「キャンセル待ちのお知らせ」（既定はテスト）

### 4. 集計の不足を埋める（hubstats）
- 予約の状態に `無断キャンセル` を足す（管理画面で選べるように）→ 集客概要の「無断キャンセル」が出る
- 「新患の次回予約率」：初めての方の予約のうち、その後に同じ方の予約があるかを **GAS の中で数え、件数だけ** 返す（個人を特定できるものは渡さない）

## 予約システムとの約束（院内アプリ側は入った）

`POST /api/marketing/reservation-notify`（ヘッダー `x-reservation-secret`）。宛先はいつも予約の行の `LINE通知キー`（sealed）。

| kind | 送るもの | 返事と、予約システムがすること |
|---|---|---|
| `patient-remind` | `sealed`・`name`・`date`（YYYY-MM-DD）・`time`（HH:MM）・`reservationNo` | `delivered:true` → `前日通知日時` を入れる（メールは送らない）／`delivered:false` → メールのある方はメールで送る（今までどおり）。`test:true` のときも患者さんには届いていないのでメールへ |
| `patient-waitlist` | `sealed`・`name`・`date`・`time`（空いた枠の開始） | `delivered:true` → その方を「案内済み」にして、1時間たっても空いていれば次の方へ／`deferred:true` → 時間外。8時を過ぎたらもう一度／`optedOut:true` → その方は飛ばして次の方へ／`test:true` → 「テスト済み」にして同じ枠では送り直さない |

- どちらも、本人が LINE で「予約のお知らせ停止」と送っていれば `optedOut:true`（送らない）。同じお知らせを二度頼まれたら `duplicate:true`
- 予約フォームの「前日にお知らせを受け取る」のチェックを外した予約は、予約システムが `patient-remind` を頼まない
- 自動化設定の既定は「テスト」。テスト中は院長の LINE にだけ見本が届き、動いた記録に残る
- 集計（`?api=hubstats`）に足すもの：`statuses`（選べる状態の一覧。`無断キャンセル` を含める）と `followup`（`{ since, windowDays, firstVisits, withNext }`。件数だけ）。院内アプリは受け取れるようになっていて、来るまでは「未取得」と出す

## 進め方
1. 院内アプリ側（関門・自動化設定・記録）を先に作り、PR にする（既定はテストなので、入れても患者さんには届かない）
2. GAS 側を作り、院長の確認のうえ Apps Script に入れて再デプロイ（テストで院長の LINE に届くのを確かめる）
3. 1週間ほどテストで動いた記録を見て、問題がなければ「動かす」に
